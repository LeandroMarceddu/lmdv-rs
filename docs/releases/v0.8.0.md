# lmdv 0.8.0

Default-handler integration on both desktops, and a scroll fix for large
documents.

## Make lmdv the default for Markdown files

Settings → General now has one row on Windows and Linux.

- **Linux** applies at once. It reuses an existing usable `lmdv.desktop` byte
  for byte (the development installer's launcher wrapper stays in charge), or
  writes a managed entry for the AppImage or the running binary, plus the icon.
  Then it names `lmdv.desktop` first for `text/markdown`, `text/x-markdown` and
  `application/x-markdown` in `mimeapps.list`, under both default and added
  associations, keeping every other handler. No root, no `xdg-mime`/`gio`
  dependency; a second press changes nothing.
- **Windows** registers the same per-user keys as the installer — `lmdv.md`,
  `OpenWithProgids`, `RegisteredApplications` and `Capabilities` — then opens
  Default Apps (filtered to lmdv on Windows 11) with an Open-with fallback.
  Windows protects `UserChoice`, so the final choice stays the user's; lmdv
  never reads, deletes or forges it.

The row explains which of the two happens on the current system. It is absent
on platforms without a hand-off.

## Scrolling large documents

The delay on fast wheels was not vsync or the glide: the reading view passes
app handlers, which made the renderer's per-block cache unreachable, so every
wheel frame rebuilt the entire article. On a 951 KiB, 15.5k-node developer guide
that was 49.9 ms of CPU per frame (20 FPS); layout was only 0.13 ms.

- The article is now reused across frames (Rune's `memo`) until something it
  actually draws changes: document revision, theme, width, scale, highlights,
  open details cards, the active tab/mode, or the table copy mark. Documents
  that draw a picture or diagram are built again, because an image decodes on a
  worker and a diagram follows the appearance.
- The wheel glide follows the wheel's speed: Rune's smooth 0.32 s spring for a
  single notch or a wheel after a pause, stiffening to 0.10 s during a burst.
  A fast burst trails about 72 pt instead of ~300, while one notch feels
  exactly as before.
- Release measurement at 1200×860: **20 → 41 FPS**, view work **15.5 → 1.9 ms**,
  burst trail **297 → 117 pt**; at 900×700, 46.5 FPS. 60 FPS on this document
  needs cheaper Rune commit/paint or a virtualized article; normal documents
  reach the desktop refresh.

There is no frame-rate setting yet: this Rune revision has no per-window present
mode or refresh cap, and every surface already presents at the desktop's
refresh. The speedup is the fix the reporter asked for; no frame-rate setting is planned.

## Assets

- Linux: `lmdv-0.8.0-x86_64.AppImage` and the raw `lmdv-0.8.0-x86_64`.
- Windows: `lmdv-0.8.0-installer.exe` and the raw
  `lmdv-0.8.0-windows-x86_64.exe`. The installer keeps the per-user install
  and `.md` registration; the raw binary is new.

## Known gaps

- Windows remains compile-checked and installer-built, not runtime-supported:
  the registry writes, Default Apps filter and Open-with fallback need a manual
  Windows 10/11 check (OI-155).
- 60 FPS on very large documents needs Rune-side commit/paint work or article
  virtualization.
- Docs with a picture or diagram keep the old per-frame build path; the fix
  belongs in the renderer's wired-tree memo.

## Under the hood

- `lmdv-io::assoc` replaces `windows_assoc`: shared request/result types, the
  Windows registry planner and the Linux XDG writer. The planner stays pure and
  tested on Linux.
- Six locales at 633 keys; four Rune patches; full workspace gate green.
